# Security and privacy

- **The human always pays.** Only `set_cart_quantities` and `add_recipe_to_cart` write, and only cart quantities (both through the store's `set_quantities`). The stores' own "add recipe" and "clear cart" calls are forbidden in `tests/test_safety.py`.
- **Personal data stays on your machine.** Every tool answer goes through `privacy.scrub()`. Name, address, phone, email, door code and delivery notes are replaced with `[fjernet af handle-mcp]` before the model sees them. Free text from a store (warnings, messages, errors) is also searched for emails, phone numbers and addresses.
- **Logins** live in your OS keychain, env vars or `~/.config/handle-mcp/` (chmod 600; on Windows the user profile's permissions, [ADR 0004](adr/0004-windows-has-no-file-modes.md)). Never in code, config in git or test fixtures. `handle-mcp login` uses the password for one login and saves only the store's session, never the password ([ADR 0003](adr/0003-save-the-session-not-the-password.md)). On macOS other programs running as you can read keychain items without a prompt; a stolen session dies when you log out at the store or change the password.
- **stdout is JSON-RPC.** Logs go to stderr. httpx request logging is off, because some store URLs contain account ids.
- **Store text reaches the model.** Product names, offer texts and cart messages come from the stores and land in the model's context. A store (or a seller) could put instructions in them. The server cannot order or pay, so the damage is limited to a wrong cart. Check the cart before you pay.
- **Versions.** The install commands use `handle-mcp@latest`: uvx checks PyPI at each start and runs the newest release. A push to `main` never reaches your machine; only a tagged release does, and PyPI gets it from `.github/workflows/release.yml` with Trusted Publishing (no upload token exists, and the maintainer approves each deploy). Want to choose when to update? Pin a version, e.g. `handle-mcp@1.5.2`. Why: [ADR 0008](adr/0008-install-the-latest-release.md).
- **The website** (handlemcp.dk) counts visits and button clicks with [Umami Cloud](https://umami.is): no cookies, no IP addresses stored, Do Not Track respected. The MCP server talks to the stores, and sends anonymous usage counts to Umami Cloud: starts, first tool call, logins and filled carts, with no id and no personal data in the events (Umami sees the IP address and does not save it). Exactly what is sent: [README#brugsstatistik](../README.md#brugsstatistik). Off with `HANDLE_TELEMETRY=0`, `DO_NOT_TRACK=1` or `--no-telemetry`. Why: [ADR 0005](adr/0005-anonymous-usage-counts.md).
- Use one client at a time per store. Close the store's app or website before an agent changes the cart.
- Be kind to the stores: the server makes few calls, mostly one at a time per store, and retries only on timeouts, network errors, 429 and 5xx.
